# Seam audit: step mode (021) and test-author automation (024), 2026-11-19

The owner's question, after six bugs found one live step at a time: audit the process, or test
it in CI? Both (owner decision 2026-11-19). This audit comes first. Integration tests in CI on a
kind cluster are roadmap item 025.

**Why the bugs got through.** Decision logic has 84–93% unit coverage, and none of the six was
there. The glue that talks to Kubernetes, GitHub and processes has 15–22%:
- `cli`, `pipeline`, `worker`, `checks`, `cluster` and `grader`.

Unit tests with fakes can't see a seam: a template and the code that reads it, a setting and
the rule that uses it, or a process and the terminal it inherits.

## Checklist (reuse it for every feature that adds a command, a Job or a loop)

| Seam | Question | 021/024 result |
|---|---|---|
| Command wiring | Does every command load what runs load (images, credentials, approvals, verbosity)? | Fixed earlier: `author watch` didn't load images (#112) |
| Template ↔ code | Does every label, name and selector the code looks up exist in the template it renders? | Fixed earlier: A01 looked for `app=worker`; the author pod is `app=author` (#113). Checked: the probe's service account `author` exists in `author-ns`; A05 reads netpol `proxy`, which `egress.yaml.tmpl` names |
| Setting ↔ rule | Does a new check use the same rule as the code path it guards? | Fixed earlier: step mode required `PILOT_GITHUB_ISSUES` while runs don't (#121) |
| Cross-component rule | Can two components produce the same name (files, branches, namespaces)? | Fixed earlier: a hidden test reused the worker's file path (#115). Checked: author namespaces `pilot-a-*` don't collide with worker `pilot-w-*` or grading `pilot-g-*` |
| Processes | Does a subprocess inherit a terminal, signals or environment it shouldn't? | Fixed earlier: step mode's run inherited the terminal (#122). Checked: the author Job has no terminal; `author watch` asks nothing |
| Timing | Is every wait for the owner longer than the poll interval, and is what happens between polls still shown? | Fixed earlier: the status PR was merged between passes (#124) |
| Telling the owner | Does every wait or skip say what to do, and where (a link)? | Fixed earlier: wait lines (#123). **Fixed here:** unproposed items say which label to add, with the issue link; a pass with no candidates says why, once |
| Loops | Can a failure make the loop repeat the same action every pass? | **Fixed here:** an automatic draft that already failed for a spec version was retried every pass (024 refuses it, but step mode asked again); it now comments once and waits for the owner |
| Cost per pass | Does a pass do expensive work it doesn't need? | **Fixed here:** with a run in flight, every 15 s pass cloned the target and companion for a readiness check it didn't use; it now skips it |

## Known limits (not fixed here)

- **A run that crashed while `in-progress`** (not paused, no watcher) counts as active forever,
  so it holds the target's slot. Workaround: finish or audit it by hand. A rule ("in-progress
  with no event for an hour is stale") belongs with 025, which can test it.
- **Changing the active Spec Kit feature** moves the evidence root. Runs that step mode started
  are found through `decisions.jsonl`. Earlier automatic drafts aren't, so an item could be
  drafted again after the feature changes. That's rare: the feature changes only between
  roadmap items.
