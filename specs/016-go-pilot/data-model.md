# Data Model: Go pilot at parity

The persisted data doesn't change: run evidence, config files and the fixture roadmap keep the
formats defined in `specs/002-m1-gated-pilot/contracts/`,
`specs/012-agent-approvals/contracts/` and `specs/004-github-loop/contracts/`. This file maps
the reference modules to Go packages, and defines the few new artifacts.

## New artifacts

### Golden expectations (`specs/016-go-pilot/golden/audit-expected.json`)

| Field | Type | Rule |
|---|---|---|
| `generated_by` | string | `"python reference <git sha>"` |
| `records` | list | one per committed pilot record |
| `records[].path` | string | repo-relative evidence directory |
| `records[].final` | bool | `teardown.jsonl` exists |
| `records[].rows` | list | `{id, result, detail}` in audit order |

Generated once by a tool from the Python reference, and never regenerated by tests. 8 records
and 86 rows today.

### Shared vectors (`specs/004-github-loop/contracts/vectors/`)

See contracts/parity.md. Each case has a `name`, its `input`, and `expect` (accepted comment
id or null, plus a reason per candidate; or ok/reason for status PRs).

### Watcher state (`pilot/runs/<id>/github/`)

| File | Content |
|---|---|
| `watch.pid` | the pid of the detached watcher; removed on exit |
| `watch.log` | the watcher's stdout and stderr (no secrets) |

### `run.json` addition

`impl`: `"go"` (missing means a run made by the reference). It's additive, and the audit ignores
it.

## State transitions

Unchanged from the reference: `in-progress`, `paused(awaiting-mode|awaiting-retry|awaiting-merge|awaiting-publish)`
(with `pending.status_pr` for the status-change PR), `succeeded`, `failed(<reason>)`. The
watcher reacts only to the `paused(...)` states.
